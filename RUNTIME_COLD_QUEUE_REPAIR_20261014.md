# Cold start and four-client runtime repair

The 3,000-record coverage batch adds English search bindings to existing catalogue IDs. It does not add 3,000 physical cards. The pinned 87-input manifest preserves the original ordered 65 inputs and the later 86-input prefix. The database remains 70,006 source-version/family records (42,911 English and 27,095 Japanese), 45,438 language/set/number groups, 49,916 normalized variant identities and 20,090 unresolved family labels. Verified physical printing coverage remains unknown.

The unpromoted revision `00060-jay` passed 19 of 21 acceptance gates. The second run passed the real cold-start request in 8.888 seconds; four-client capacity failed with 15 bounded busy responses. Neither failed acceptance run authorizes promotion. Existing canonical traffic stays on its recorded baseline until a new candidate passes every gate and independent review.

The repair introduces a bounded index of native source-evidence contexts. Complete historical evidence dependencies expand exact card, coordinate and release scopes; known cards outside that union have an explicit native absence result. Templates contain evidence contexts, with no raw identity row, user question, ranking, inventory, price or transaction state. Every lookup, including absence and fallback, checks the current read-only file, source alias, namespace and protected clone. Returned objects are fresh copies. Raw language, set, number, variant, eligibility and rarity are rendered from the incoming row; official rarity retains the original value as `source_rarity`.

The local feasibility audit covers all 70,006 records: 4,735 have source-context dependencies and 65,271 share the native absence result. Thirteen alternating trials measured a 20.47% host improvement. These measurements do not prove cloud capacity. The compact artifact must pass the unchanged 32 MiB metadata, 192 MiB decoded allocation, one-million aggregate JSON-token and depth-32 limits. Startup overlaps bounded artifact file reads with one database checksum task, using the original absolute deadline and joining before decoding or restoring facts. Hash acceptance and all later identity checks remain mandatory; operation timing fields overlap and must not be summed. HTTP computation still has one worker. SQLite retains normal read-only locking and change detection. Immutable and shared-cache experiments were rejected.

The first PR #8 head passed ordinary tests but failed both Linux image checks while constructing the native context index within eight seconds. The follow-up constructor validates all historical media subjects and identity holds once, including stale or held evidence, then discards the temporary facts. The complete historical correction snapshots and new-card records prove correction absence outside their exact ID union. Native metadata and printed-artist formatters reuse that constructor result; their ordinary entry points still validate the current database. Unsupported inputs disable the entire optimization and retain native membership, while malformed evidence and a changed database or source abort the build. Temporary facts, templates and their ID sets remain bounded; no callback or supplied cache can enter this compiler.

The retained comparison at the first PR head matched all 70,006 complete card responses and their value types across the previous native renderer, current native renderer, materialized model and strict loaded artifact. A separate constructor experiment measured a 40.81% median host reduction, from 4.385 to 2.596 seconds, with model contents unchanged. Each new source revision still requires its own complete response proof, exact Linux CI results and private cloud acceptance. Those local measurements do not approve deployment or establish four-client capacity.

Coverage remains 9,364 localized bindings and provider mappings (4,333 English, 5,031 Japanese), with 3,000 new English bindings, 1,503 groups and 48 releases. Card IDs, source records, relationships and all 51 historical database tables are preserved. Image fact evidence remains 1,449 events for 1,141 subjects; scan/number evidence remains 1,486 events for 1,171 subjects. Those counts do not measure actual image-file availability. Display approvals, automatic offer joins, purchases, marketplace prices and commerce records remain zero. Pocket stays excluded. Buy&Ship remains the intended MoR; Pivota holds no customer funds.

Frontend integration retains the existing response contract. Keep `source_rarity` and raw primary endpoint snapshots beside any effective rarity. Cross-language counterparts remain relationships between separate identities; a shared template, artwork or collector number does not equate SKUs, variants or prices. This backend patch does not edit the creator frontend or adopt its separately authorized image acquisition.

The subsequent private candidate `00062-fop`, built from merged source `0d81a7a96ca3602c97ce53f4401192aff76f9084`, failed required-artifact startup at the unchanged eight-second deadline. Its retained traceback reached the allocation/count validation phase; it does not establish an out-of-memory failure. No candidate acceptance or promotion followed. Canonical traffic remained on `00053-buz`, with the prior tags, IAM and independently owned image revisions preserved.

The next repair changes only the JSON string-token regex to use possessive ordinary-byte runs and repetitions, supported by the project's Python 3.11 minimum. Its alternatives retain disjoint prefixes and cannot consume an unescaped closing quote. Tests compare the released pattern's match spans, exact bytes, stripped tokens, decoded values and Python types against the replacement, including malformed escapes, Unicode, duplicate keys, nonfinite values and the actual byte, depth and aggregate-member limits. The pinned metadata retains 668,386 outer tokens and 931,659 aggregate tokens across 3,936 unique nested roots. Unanchored scanning retains the existing quadratic malformed escaped-quote case; this change makes no global linear-time or independently interruptible-regex claim. Allocation accounting, hash binding, file identity checks and deadlines remain unchanged. Host timing improvements still require exact-source Linux checks and the complete natural-cold cloud acceptance before promotion.

Source rollback reverts this runtime patch and rebuilds the same pinned manifest; it leaves coverage inputs and legacy IDs intact. Cloud rollback is available only after an owned promotion receipt exists: use its recorded previous canonical revision and restore the recorded routing while preserving all tags, IAM and settings. A staged-only receipt cannot authorize rollback or a default traffic change. Final deployment receipts and acceptance results must identify the exact merged source, image digest and catalogue revision.
