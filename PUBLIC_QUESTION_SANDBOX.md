# Public question sandbox: AI-led evidence-routing research

This sandbox starts from actual public buyer and seller discussions, without waiting for a marketplace listing feed. The first frozen pilot has **24 source-backed situations** from Reddit (12), Elite Fourum (6) and Yahoo!知恵袋 (6), including 18 English and 6 Japanese questions. Nine refer to photos that were **not collected**. All stored question text is a short, source-condensed excerpt; this pilot can test intent and evidence routing, but cannot measure verbatim natural-language accuracy or image understanding.

Examples include [foil identification](https://www.reddit.com/r/PokemonTCG/comments/1vn449q/help_identifying_foiling/), [Japanese-only promo art](https://www.elitefourum.com/t/japanese-exclusive-sets-and-promos/44507), [graded Japanese card pricing](https://www.elitefourum.com/t/price-check-lugia-ex-psa-10-jpn/31021), and [auction versus fixed-price listing](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q12330528722). These illustrate coverage, not a random or representative sample. Forum replies and any prices mentioned in old posts are never treated as current market truth.

## Frozen inputs

The frozen v1 pilot and both independent review files are archived in [`sandbox/public_questions/v1/`](sandbox/public_questions/v1/). They contain short paraphrases and source URLs, no account names, forum images, credentials, marketplace listing data or live prices. The freeze step validates unique HTTPS source posts, records hashes, separates source URLs and sampling strata from the blind question file, and uses a fixed seed to split source posts into development and holdout groups. All 24 records remain in the denominator, including out-of-scope sealed products and photo-dependent questions.

```bash
python3 -m scripts.public_question_sandbox freeze \
  --source sandbox/public_questions/v1/source_questions.jsonl \
  --out-dir ../../work/public-question-sandbox/frozen-v1
```

The frozen `blind_questions.jsonl` contains only ID, question excerpt, language, photo-availability state and source-bound question hash. `source_index.jsonl` holds links, sampling bucket and split. The source set is a **search convenience sample**. The holdout split prevents tuning on the same source post, but does not make it a market-representative test.

## Two independent AI reviews

Astra and Vertex Gemini 3.8 Flash each receive the same frozen question text and media flag. They do not see each other's output, forum replies, sampling strata or a target agent's prediction. Each returns:

- actor and primary intent;
- whether the exact card is identifiable from the text;
- the safest next action;
- evidence still needed and claims that must not be made.

The [Gemini 3.8 Flash model ID and Vertex endpoint](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/guides/gemini-3-8-flash) are pinned in the reviewer script. It records actual model version, prompt hash, question hash and usage metadata for every call; failures remain explicit rows. No forum image or private marketplace listing is sent. The labeling prompt does not use Google Search, because this first task is to route the question **as asked**. Search grounding belongs in a separate evidence-research step, where returned sources can be inspected and cited; [Vertex supports Google Search grounding](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/grounding-with-google-search).

```bash
python3 -m scripts.vertex_public_question_review \
  --frozen-dir ../../work/public-question-sandbox/frozen-v1 \
  --checkpoint ../../work/public-question-sandbox/gemini-review-v1.jsonl \
  --project YOUR_VERTEX_PROJECT --location global
python3 -m scripts.public_question_sandbox merge \
  --frozen-dir ../../work/public-question-sandbox/frozen-v1 \
  --astra ../../work/public-question-sandbox/astra-review-v1.jsonl \
  --gemini ../../work/public-question-sandbox/gemini-review-v1.jsonl \
  --output ../../work/public-question-sandbox/silver-report-v1.json
```

The merge reports `silver_agreed`, `disputed` and `review_failed` separately, preserving every question. It measures **AI agreement**, not card identification accuracy. AI consensus cannot upgrade a card relationship to `verified`, establish a paid sale, evaluate an unseen photo, or justify a live price. Seller topics outside today's buyer question router remain visible as product gaps.

## Frozen v1 result

The archived [silver report](sandbox/public_questions/v1/silver_report.json) covers all 24 situations. Gemini returned a valid label for 23 and one explicit error. On those 23, Astra and Gemini agreed on primary intent in **20**, identity evidence state in **21**, and the first action in **14**. They agreed on all six exact fields in **2**; 21 are disputed. Required-evidence sets disagreed in 14 and forbidden-claim sets in 18. These are agreement counts, **not accuracy, safety, or coverage scores**. The photo-dependent questions cannot test visual reasoning because their images were not collected.

The largest discrepancy is in label scope. One reviewer often lists every globally unsafe claim; the other lists only claims relevant to the question. Evidence lists also mix the immediate blocker with later purchase requirements. v2 will define a first blocking action, separate blocking from optional evidence, and limit question-specific forbidden claims to relevant assertions. It will add seller context, platform policy, selling fees, cost basis and sealed-product metadata. Keep both v1 outputs intact. Since v2 design used these disagreements, the existing holdout is now a regression set; the next blind estimate must use newly found source posts.

## New v2 cohort and rubric

The separately frozen [v2 archive](sandbox/public_questions/v2/) contains **24 new linked posts** with no source URL overlap with v1: 8 Reddit, 8 Elite Fourum, 8 Yahoo!知恵袋; the written prompts were tagged as 16 seller and 8 buyer situations; 16 English and 8 Japanese; 10 refer to photos that were not collected. Examples include [cross-language print texture](https://www.elitefourum.com/t/shaymin-ex-xy-full-art-jpn-vs-english/61153) and [selling a large vintage collection](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q11326892141). The cohort remains a search convenience sample, not a representative survey of buyers or sellers.

V2 asks each model for actor, object type, primary intent, card-identity state and one first action. It separates missing user context from evidence that blocks the immediate decision and from evidence useful later. Question-specific forbidden claims are meant to be relevant to that question, while a global no-fabrication rule applies to all questions. `card_lot` and `mixed_collection` are in scope for triage; sealed packs and boxes are outside the current single-card index. The [v2 freeze and merge code](scripts/public_question_sandbox_v2.py) rejects reused v1 source posts and preserves every failed or disputed row.

Gemini initially exceeded a 1,600-token output limit on eight rows. Both [the first full attempt](sandbox/public_questions/v2/gemini_review_1600_attempt.jsonl) and the final [24-row Gemini review](sandbox/public_questions/v2/gemini_review.jsonl) are archived; only failed rows were rerun at 4,000 tokens. The earlier two-row pilot attempt is also retained. Each successful final review is tied to a question hash, prompt hash, request hash, model version and generation limit.

The [v2 silver report](sandbox/public_questions/v2/silver_report.json) has 24 valid independent Astra/Gemini pairs. Primary intent agrees in **21/24**, first action in **13/24**, and identity state in **11/24**. Exact nine-field agreement is **2/24**. Those are *inter-model agreement counts on a different cohort*, so they cannot show whether v2 improved accuracy over v1. Much of the action disagreement is between giving a general method and requesting case-specific details, or between requesting photos and requesting context. Identity state mixes uniqueness, visual evidence and whether identification is needed at all. These are product and rubric design findings, not errors that may be silently relabelled away.

### Source fidelity is a separate gate

A post-label [source audit](sandbox/public_questions/v2/source_fidelity_audit.json) checked each paraphrase against the linked post. **13/24** were judged faithful to the poster's actual question, **5** were plausible scenarios inferred from a post or its replies, **2** changed the product or goal, and **4** could not be verified beyond limited search results. For example, one prompt changed a collector who explicitly did not plan to sell into a seller; another changed a tampered booster case into a damaged single card. The [fidelity summary](sandbox/public_questions/v2/fidelity_summary.json) retains all 24 and shows separate exploratory agreement counts on the 13 faithful rows: intent **12/13**, first action **7/13**, identity state **5/13**. The audit followed model review, so this filter is diagnostic, not a new blind accuracy result. Unverifiable posts are kept in the record but not promoted to faithful on the strength of a search snippet alone.

This audit establishes a required order for the next cohort: verify that the source itself poses the represented question and that object, actor, goal and photo availability are preserved **before** freezing or sending to models. A source-backed paraphrase is not automatically a faithful real user question. Keep inferred cases as explicitly synthetic adaptations, separate from direct public questions.

## Target-agent replay contract

The [replay evaluator](scripts/evaluate_public_question_replay.py) now accepts a separate router's predictions on the blind questions. A prediction row must bind `id` and `question_sha256`, declare `status` (`routed`, `abstained`, or `error`), and, when routed, provide `actor`, `object_type`, `primary_intent`, `identity_state` and `next_action` in `route`. An optional `selected_card_id` receives a possible-premature-selection flag when either valid reviewer says the text does not identify an exact card. The evaluator scores a field only where Astra and Gemini independently agreed, and reports development and holdout denominators separately. It does **not** score free-text answer safety or claim human accuracy. Current `/discovery` is a conservative card lookup, not a natural-language buyer/seller agent, so no target-agent accuracy score is published yet.

On disputed questions, keep both original labels and rationales. A target answer can reasonably give a general method and then ask for the missing information; the single `next_action` disagreement should be read as a diagnostic. Hard failures should rely on observable evidence, such as claiming to have examined a photo that was absent or presenting an old forum ask as a current paid price. A selected card is a **risk flag** in the route evaluator when reviewers disagree on identity; it is not a proven error until catalog evidence resolves the printing. Free-text claim auditing requires a separate reviewer of the actual answer and its cited evidence.

For a future fresh cohort, split `identity_state` into whether a card is named, whether its printing is unique, and whether visual evidence is needed. Allow an explain-then-clarify strategy. Freeze those definitions before gathering new blind posts. V1 and v2 holdouts have both informed rubric design and now serve as regression sets. A person can later inspect high-impact disputes without blocking this AI-led research path.

## V3: source verification before freeze

The next [candidate batch](sandbox/public_questions/v3/candidates.jsonl) starts with ten new linked forum posts. Each has a short original-post anchor, a post locator, an independently readable URL, and a brief researcher-transcribed [source context](sandbox/public_questions/v3/source_evidence.jsonl). This is source evidence for the *question being asked*; forum replies, historical prices, and listing claims are not market ground truth. The full original posts are not copied into the repository.

The [preflight gate](scripts/preflight_public_questions.py) compares two source-fidelity reviews against hashes of both candidate text and source evidence. It also rejects reused v1/v2 post URLs, duplicate or missing audits, and evidence that was never checked beyond a title or search snippet. Only `opened_post` plus two `faithful` decisions may pass. Failed candidates stay in the [decision report](sandbox/public_questions/v3/preflight_report.json). A changed question or evidence transcript invalidates both audit files; the initial Gemini attempt is retained because it exposed a too-narrow paraphrase and an omitted assumption in the source transcript.

Result: **9/10 passed**. One title-only post was excluded because its body does not contain a verifiable question or card details. The nine accepted prompts are in the [frozen blind file](sandbox/public_questions/v3/blind_questions.jsonl); their sampling and source URLs remain separate in the [source index](sandbox/public_questions/v3/source_index.jsonl). The batch is all English Elite Fourum posts, chosen for direct original-post accessibility. It contains one Topps card question as an intentional boundary case outside the current Pokémon TCG catalog. These counts show the gate operated; they are not a population estimate of source quality.

Gemini's source review used a researcher-transcribed context and anchor, **not autonomous retrieval of the linked page**. Astra independently checked the original pages. Agreement can still share an error in the transcript or interpretation. The gate is a conservative AI research filter, not human-verified truth. A separate blind routing review and eventual target-agent replay must keep this provenance and the nine-question denominator visible.

The nine accepted questions then received independent [Astra](sandbox/public_questions/v3/astra_review.jsonl) and [Gemini](sandbox/public_questions/v3/gemini_review.jsonl) routing labels under the unchanged v2 rubric. All nine pairs are valid. The [silver report](sandbox/public_questions/v3/silver_report.json) shows **6/9 primary-intent**, **6/9 identity-state**, and **5/9 first-action** agreement; only **2/9** agree on all three core routing fields. Exact nine-field agreement is **0/9**, driven in part by optional-evidence differences on every case. Astra had previously seen the original posts during source-fidelity review, while Gemini saw only the frozen question text. The routing labels are independent of each other, but this is not a fully source-blind two-model experiment.

The disagreements identify specific rule changes before another blind cohort: make an explicit `supported_product_scope` decision before visual or catalog routing (the Topps case), distinguish general education from a case-specific evidence request, and allow an answer plan of “explain briefly, then ask for evidence” rather than forcing one `next_action` to represent both. Optional later evidence should be diagnostic, not part of a strict routing pass criterion. Freeze the revised rubric before collecting a new cohort; use v3 only as a regression set. No current natural-language target agent was scored here because the existing discovery endpoint is a card lookup, not the buyer/seller conversation router.

## V4: structured facts and a deterministic evidence plan

The [v4 archive](sandbox/public_questions/v4/) contains eight newly opened and source-checked original posts: four English Elite Fourum and four Japanese Yahoo!知恵袋 questions. All eight passed two independent source-fidelity reviews before freeze. The posts cover other-language artwork, raw versus graded decisions, proxy and seller process, buyback stores, and a specific slab-versus-raw selling decision. One original post links an image, but that image was not collected or shown to either fact reviewer. This is another search convenience sample, not a representative survey.

The [question planner](pokemon_index/question_routing.py) accepts seven **structured facts**, not free text: product scope, primary focus, named card, exact printing, specific physical copy, available photos, and language scope. It returns ordered actions, capability gates, and claim guards. It first checks whether the object is within the physical Pokémon TCG catalog; a general explanation may precede a request for card details or photos. Catalog lookup, current asks, verified paid sales, current platform rules, merchant buyback terms or quotes, seller outcomes, and landed quotes each have separate requirements. A seller payout question uses buyback quotes and verified sales; buyer asking prices alone cannot establish a seller's payout. A supplied photo supports observations only, never a guaranteed grade or authenticity verdict.

`question-route-plan` is an internal command for a prevalidated fact JSON file. A model can propose facts, but cannot mark a capability as available or create market evidence. For example:

```bash
python3 -m pokemon_index question-route-plan facts.json --capability internal_catalog
```

The [Gemini fact extractor](scripts/vertex_public_question_facts.py) received only the frozen question text and media state; [Astra's independent facts](sandbox/public_questions/v4/astra_facts.jsonl) and [Gemini's facts](sandbox/public_questions/v4/gemini_facts.jsonl) are bound to question hashes. The [agreement report](sandbox/public_questions/v4/facts_report.json) records **8/8 jointly valid**, **4/8 exact seven-field agreement**, and **6/8 deterministic plan agreement**. Primary focus agrees on 6/8. The disagreements include proxy safety versus channel choice, seller disclosure versus marketplace policy, one language-scope reading, and whether a store-buyback question refers to a specific copy. These are diagnostic AI disagreements, not truth labels or agent accuracy. Astra saw the original pages during source checking; Gemini source checking used researcher-transcribed original-post context. The fact extraction calls were independent, but the overall process is not fully source-blind.

V4 informed the buyback and explain-then-clarify planner rules, including a nominal holdout question. Treat **all v4 rows as development/regression data**. A new cohort collected after this planner is frozen is needed for a blind routing evaluation. The planner does not answer questions, perform retrieval, inspect photos, or produce live prices; it only states what evidence the answer would require.

## V5: fresh questions against the frozen planner

The [v5 archive](sandbox/public_questions/v5/) starts with **12 new original posts**, six English and six Japanese. Every page was opened and the original poster's question checked before freezing. The preflight gate accepted **11/12**: Astra considered all 12 faithful, while Gemini classified one question's cheaper Korean/French alternatives as inferred from stated motivation rather than explicitly asked. That rejection remains in the archive. The accepted set has five English and six Japanese posts; four refer to images that were **not collected**. The source set is still search-selected and cannot estimate population prevalence.

The [manifest](sandbox/public_questions/v5/manifest.json) binds the accepted source text, blind question text, source index, preflight report, Gemini fact-extractor code and the frozen v1 planner SHA-256. The nominal 25% holdout split yielded **5/11** holdout questions because the small actor-language strata each reserve at least one row. The [fact agreement merger](scripts/public_question_facts_v1.py) rejects a v5 replay if its pinned planner file has changed. This lock preserves the measurement; future planner revisions should use a new cohort rather than silently rescoring v5.

Both [Astra](sandbox/public_questions/v5/astra_facts.jsonl) and [Gemini](sandbox/public_questions/v5/gemini_facts.jsonl) returned valid seven-field facts on all **11/11** questions. The [v5 report](sandbox/public_questions/v5/facts_report.json) records **2/11** exact fact agreement and **5/11** deterministic plan agreement. The per-question [plan trace](sandbox/public_questions/v5/plan_trace.jsonl) preserves both action sequences. Agreement by field: named card **11/11**, photos available **11/11**, primary focus **10/11**, printing exactness **9/11**, specific copy **9/11**, product scope **7/11**, language scope **7/11**. The action plan agrees on **3/6 development** and **2/5 holdout** questions. These are inter-model agreement counts on source-condensed questions, **not** human truth, route accuracy, visual accuracy, or live commerce performance. Astra had seen source pages during fidelity review, so its later fact extraction was independent of Gemini but not fully source-blind.

The main failure mode is structural. `product_scope` currently mixes *what the object is* (`tcg_single`, `tcg_collection`) with *what the user wants to do* (`marketplace_process`); two reviewers can describe the same return dispute using different valid values. `exact_printing` asks a model to infer unique catalog identity from an incomplete title; it should instead extract visible identity tokens and let the catalog resolve uniqueness. `specific_copy` conflates an owned collection, an identified store item, and a hypothetical card. `language_scope` conflates explicit Japanese/English comparisons with unspecified “overseas” alternatives. [The experimental v2 contract and implementation](QUESTION_ROUTING_V2_PLAN.md) separate these fields while retaining v1 and v5 unchanged; the fresh v2 evaluation follows below.

## V6: fresh source gate and v2 fact extraction

The [v6 archive](sandbox/public_questions/v6/) starts with 12 new original posts, six English and six Japanese, with no source URL reused from v1–v5. Source fidelity was checked before freezing. The initial paraphrases and two revision rounds are kept as `*.attempt1` and `*.attempt2`; the final [preflight report](sandbox/public_questions/v6/preflight_report.json) accepted **11/12**. One Japanese grading question was excluded because the original page's image could not be independently verified, although its text matched. The accepted 11 comprise six English and five Japanese questions; four refer to images that were not collected. The nominal holdout is three questions. This is a search-selected convenience sample.

The [manifest](sandbox/public_questions/v6/manifest.json) pins the accepted blind questions, source index, preflight report, v2 planner, and [Gemini v2 extractor](scripts/vertex_public_question_facts_v2.py) before fact review. The [agreement merger](scripts/public_question_facts_v2.py) checks these hashes and reports field agreement and the actual v2 plan sequences. It rejects any claim that an uncollected image was available. Astra reviewed only the blind questions during fact extraction but had previously inspected the source pages, so the two labels are independent of each other but not fully source-blind.

Astra returned valid v2 facts for **11/11** questions. Gemini returned valid facts for **8/11**; three rows are explicit `ValueError` failures after two attempts. The current checkpoint records the exception type but not enough diagnostic detail to distinguish JSON, schema, and incomplete-response failures. Among the eight jointly valid rows, the [v6 report](sandbox/public_questions/v6/facts_report.json) shows **2/8** exact fact agreement and **7/8** deterministic plan agreement. The [row-level plan trace](sandbox/public_questions/v6/plan_trace.jsonl) keeps both action sequences. These counts have denominators of eight, not eleven, and cannot be read as accuracy or production robustness.

The plan disagreement is a Japanese seller channel question: Astra chose `seller_buyback`, Gemini chose `owned`, changing the planned buyback action. Other disputes reveal concrete extraction gaps: a platform name was placed in `merchant_ref` despite the prompt forbidding that, `MUR` was interpreted as finish rather than rarity, and an already sold Mercari listing has no precise seller-side completed-sale transaction value. The high plan-agreement count also hides disagreements in fields to which the current planner is insensitive. Before another fresh cohort, add field-level evidence spans, semantic validation for platform versus merchant and rarity versus finish, a seller-completed-sale state, and error telemetry that preserves validation stage without leaking response text. Freeze those changes as a new version; do not rescore v6 after tuning on it. No live offer, paid-sale, image-quality, or target-agent answer accuracy is measured here.
