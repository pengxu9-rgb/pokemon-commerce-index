# 卡片身份与版本复核

当前 68 条旧 demo listing 仅是 **AI 辅助标注草稿**。二次证据审计后，40 条具有卡组代码和卡号候选，14 条仅有部分身份信息，14 条应弃权。虽然 3 条标题明确提及 Master Ball reverse，它们缺少卡号；目前 **0 条同时具备独立证实的卡组、卡号和版本标签**。因此不能从这批文本计算版本匹配精度。

## 给真人复核员的工作包

原始标题、URL、草稿标签和证据笔记保留在当前工作区的 `work/labeling/card_labels_draft.jsonl`，不打包到交付目录。复核时须同时查看 listing 标题、描述、卡面正反图；评级卡还要看证书编号及卡壳。图像不可用时，版本标为 `unknown`，不得由价格、稀有度或目录默认版本反推。

本地操作入口及双审、裁决、导出步骤见 `review-workbench.md`。

两位复核员独立填：`single_card`、语言、卡组、卡号、版本（`normal` / `holo` / `reverse_pokeball` / `reverse_masterball` / `unknown`）、评级机构、分数、每个字段的证据位置。分歧由第三人裁决，保留原始判断、裁决人、时间和证据 URL。多卡包、语言冲突、图片看不清及不确定的版本均应显式弃权。

## 度量口径

1. 从已授权的新 listing 中分层抽取盲测样本，覆盖热门、普通和长尾卡，不从 matcher 成功结果中挑样；旧 demo 的 68 条只用于回归和错误分析。
2. 固定目录版本与 matcher commit，再交由复核员标注；评测期间不能依据盲测结果改规则。
3. 分别报告卡片身份（语言＋卡组＋卡号）、版本、评级机构／分数的自动接纳精度和覆盖率，另报多卡及不确定样本的错误接纳数。
4. 分母包括所有抽到的 listing；只在有真人证据标签的字段上计算该字段准确率，并同时公布不可判定数量。不要把 `unknown` 当作正确版本。

`scripts.evaluate_label_draft` 只输出当前 AI 草稿与标题匹配器的**一致性诊断**，不是上述真人盲测的 precision 或 recall。
